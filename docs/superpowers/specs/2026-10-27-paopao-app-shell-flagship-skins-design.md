# 泡泡栈 App 形态：砍雷同皮肤 → 旗舰备选页

日期：2026-10-27  
状态：待用户审阅  
范围：后台「系统设置 → 应用形态」第二步备选皮肤 + 右侧真机预览 + 挑选卡缩略图  
不做：新业务功能、抽奖模块新建、改打包流水线以外的兼容层

## 背景

现网 0.1.86 备选是换皮：挑选卡只有标题+一行字；真机预览大片留白；首页单列/双列几乎一样；发现宫格不是三列；商城海报只美化第一条。用户要求备选「像分别给不同 App 做的页面」，并选定第三种做法：先砍雷同，再重做旗舰。硬约束：**保留用户当下正在使用的模板**（现网已选 skin id 不得从配置中消失，也不得在 UI 里被静默换掉）。

## 目标

1. 每页只保留 2～3 套真正不同信息架构的旗舰皮肤（布局、组件、密度可一眼区分）。
2. 挑选卡带静态缩略图（一眼能分产品差异，不必点进预览才知道差在哪）。
3. 真机预览用线上真实内容填满封面/视频/商品图；禁止空舞台、半屏留白、描述与画面不符。
4. 旧 skin id 向下兼容：已保存但不在旗舰列表的值，映射到最近旗舰，且**当前选中项若属于「保留清单」则原样保留展示**。

## 非目标

- 不删除页面模块本身（首页/社区/发现/商城/消息/我的仍可勾选）。
- 不强制打开「社区」模块；社区开关保持现网状态。
- 本期不新增「抽奖」模块（现网 catalog 无此模块）。
- 不改 Vue 正式登录、权限设置等其它 backlog。

## 砍留规则（旗舰清单）

| 模块 | 保留旗舰（展示名 → 现有/目标 id） | 默认砍掉（映射到） |
|------|-----------------------------------|-------------------|
| 首页 | **当前使用原样保留**；另做旗舰：论坛双列瀑布（关注/推荐/最新+搜索+有封面瀑布，对标用户实机图）、视频号沉浸 `feed`、社区动态卡 `haosns` | 非当前项的雷同皮肤（如空壳 `compact`/`magazine` 换皮）一律重做或下架；映射到最近旗舰，当前项除外 |
| 社区/论坛 | **当前使用原样保留**；旗舰：单列信息卡论坛、发现式圈子 `haosns` | 仅换行距的紧凑雷同砍掉；当前项除外 |
| 发现 | **当前使用原样保留**；旗舰：真三列宫格 `grid`、搜索发现 `haosns` | `shelf`/`list` 等非当前项重做或映射 |
| 商城 | **当前使用原样保留**；旗舰：全量海报 `poster`、右图商品卡 `haosns` | 非当前的半成品 `card`/`compact` 重做或映射 |
| 消息 | **当前使用原样保留**；旗舰：入口+列表 `list`、真会话气泡 `bubble` | 非当前的 demo 感皮肤重做或映射 |
| 我的 | **当前使用原样保留**；旗舰：小红书头图+双列笔记瀑布、成就动态 `haosns` | 非当前的纯文字砖皮肤重做或映射 |
| 底栏 | **当前使用原样保留**；另两套可重做质感，三套都留 | 不砍数量 |

### 保留「当下使用」硬规则

1. 读取现网 `saveAppShell` 已存的 `skins` / `tabbar`。
2. 若某模块当前 skin **不在**上表「保留旗舰」里，仍在挑选 UI 中临时保留该卡，并打「当前使用」标记，直到用户主动换成旗舰之一。
3. 映射表只作用于：从未选过、或用户主动放弃旧皮肤后的默认与迁移提示；**不得在打开页面时静默改写已选值**。
4. 验收前用截图证明：打开应用形态 → 第二步，各模块高亮项与改前一致。

## 挑选卡与真机预览标准

1. 每套旗舰一张缩略图（固定比例，可从真机预览静态导出或专用 mock 资源），卡上：缩略图 + 短名 + 一句产品定位（不是「单列版块，标题更紧」这类换皮文案）。
2. 真机预览数据继续拉线上 posts/products/banners/me；缺封面时用占位图库填满格子，**不允许**只渲染标题作者导致下半屏空白。
3. 描述与画面一致：标「视频号」必须有视频舞台或封面帧；标「三列宫格」必须是三列；标「海报」列表每条都是大图；标「小红书」笔记区双列有图。
4. 自定义扩展页仍无皮肤预览占位，文案不变。

## 交付与验收

1. 版本：在 0.1.86 基线上打 0.1.87+（vite 重编 shell-wizard + shell-phone，禁止手改混淆后的 import 别名）。
2. 交付物：GitHub Release zip + server.json；代理 :18780 与现网 :18080 盖包；前后对比截图目录。
3. 验收清单（浏览器证据，禁止口头「好了」）：
   - [ ] 第二步挑选卡有缩略图，旗舰之间布局肉眼不同
   - [ ] 每套旗舰真机预览无大片留白，封面/商品图可见
   - [ ] 打开页面后当前已选皮肤与改前一致（保留当下使用）
   - [ ] 软跳离开应用形态再进其它侧栏页，无需整页刷新
   - [ ] 旧 skin id 写入配置后仍可读；新保存只写出旗舰或「当前使用」项

## 实现落点（供计划，非处方）

- 后台：`shell` 向导组件 + `shell-phone` 预览组件 + 对应 CSS；catalog/skins 列表与文案表。
- 兼容：读写 app-shell 配置时的 skin 归一（只在保存新值或显式迁移时用映射；读路径尊重当前值）。
- 资源：缩略图进 `public/admin` 静态目录。

## 风险

- 手改 minified 别名曾导致软跳中毒；必须 vite 源码重编再指纹映射上线包。
- 无封面内容站会仍显空：预览层要有兜底图，与真实 App 空态策略可分开。

## 用户确认（2026-10-27）：除当下使用的模板外，其余模板均可重做。论坛页按实机「关注/推荐/最新 + 搜索 + 双列瀑布」收进旗舰。

## 已定决策摘要

- 做法：第三种（砍雷同 → 旗舰）。
- 范围：全部备选页一起。
- 保留用户当下使用的模板；其余全部可重做。
- 论坛双列瀑布纳入首页/社区旗舰。
- 挑选卡缩略图 + 真机填满。
- 旧 id 兼容映射，打开页不静默改选中项。
